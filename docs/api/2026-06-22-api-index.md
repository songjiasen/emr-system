# 电子病历系统接口索引

本文档记录当前已实现的微服务接口范围。所有接口统一返回 `code/message/data` 结构；前端统一通过网关访问时使用 `/cl584734139` 前缀，后端服务内部仍保留下表中的真实业务路径。

## 网关与鉴权

- 统一网关地址前缀: `/cl584734139`。
- 受保护接口需在请求头传入 `Token: <登录返回的 token>`；当前网关不使用 `Authorization: Bearer` 格式。
- 网关会清理客户端传入的 `X-User-Id`、`X-Username`、`X-Role-Code`、`X-User-Table`，Token 校验成功后再注入可信身份头给下游服务。
- 下游服务基于可信身份头做患者、医生、护士、主任和管理员的数据范围校验，避免前端通过请求参数越权查询或操作他人数据。

## 当前边界

- 核心业务数据已经接入各服务 MySQL 数据库，测试环境使用 H2 隔离库。
- 网关已接入 Token 校验、角色白名单、可信身份头透传和写操作审计。
- 患者、医生、护士、主任、管理员的粗粒度访问权限由网关控制；病历、预约、费用、诊疗等关键接口在服务端继续校验本人数据范围。
- 当前 AI 使用 `mock` provider 兜底，不依赖百度 AI Key；智能检索和调用日志已接入数据库/病历服务链路。
